# 数据来源与核实说明

本文件说明徽知平台文化数据的来源、核实方式与可信度分级。
所有事实性内容均登记在 `data/sources.json`，实体与关系通过 `source_ids` 字段引用。

---

## 一、可信度分级

| 级别 | 类型 | 说明 |
|---|---|---|
| A | UNESCO 世界遗产中心 | 世界遗产条目的官方认定信息 |
| B | 国家级政府机构 | 国务院文件、文化和旅游部、中国非物质文化遗产网 |
| C | 地方人民政府与官方媒体 | 黄山市人民政府、黄山风景区管委会、黄山市文化和旅游局、光明网、新华网、学习强国、中国文明网、人民日报客户端 |
| D | 学术与专业出版物 | 北京周报等 |
| E | 百科条目 | 仅在 A–D 未覆盖时作补充，并在来源说明中明确标注其权威性较低 |

本项目**优先使用 A–C 级来源**；E 级来源仅用于 A–D 未覆盖的细节（如许国石坊的国保批次），且在 `sources.json` 的 `note` 字段中明确写出「权威性低于官方来源」。

## 三、核实方式

1. **先检索核实，再写入数据**：每条事实在写入 `entities.json` / `relations.json` 前，均通过检索获取官方或权威来源页面确认，不使用未经核实的推测内容。
2. **每条实体与关系都必须带来源**：`source_ids` 字段不可为空 —— 这一要求已由 `tests/test_data_integrity.py` 固化为自动化测试，缺失来源会直接导致测试失败。
3. **来源引用有效性由程序校验**：`src/data/loader.py` 在加载时检查所有 `source_ids` 是否指向 `sources.json` 中真实存在的条目，断链会抛出异常。
4. **关键事实有回归测试**：世界遗产编号与年份、非遗批次与申报地区、牌坊数量、人物评选名次等关键事实均在 `tests/test_data_integrity.py` 中设定了断言，数据被误改会立即暴露。

## 四、已知的数据取舍

| 情况 | 处理方式 |
|---|---|
| 同一事实在不同官方来源中口径不一 | 采用更权威或更具体的来源，并在实体 `attributes` 中保留口径说明。例如黄山千米以上高峰数量，黄山风景区管委会口径为 88 座，UNESCO 表述为 77 座，本项目采用景区管委会口径并在来源中标注。 |
| 行政区划变迁 | 明确标注现行归属。如婺源县标注为「徽州婺源（今属江西省上饶市）」，绩溪县标注为「徽州绩溪（今属安徽省宣城市）」。 |
| 无法核实的内容 | **不写入数据集**，宁可减少实体，也不引入无出处内容。 |
| 民间传说类内容 | 仅在明确标注为「相传」的前提下收录，并给出出处。如徽州一品锅的乾隆赐名传说。 |

## 五、图片素材

图片计划从 Wikimedia Commons 等自由授权来源下载，逐一登记授权协议、作者与原始链接，汇总于 `assets/images/CREDITS.md`。

**P3 实测结论：本机网络无法访问 Wikimedia。** `commons.wikimedia.org` 的 DNS 可正常解析
（→ `103.102.166.224`），但直连、走代理、脱离沙箱三种方式在 TCP 层均超时（`code=000`）；
同环境的 `ihchina.cn`、`mirrors.aliyun.com` 返回 `200`，Openverse（`api.openverse.org`）亦不可达。
**结论：网络阻断，非代码问题。**

因此本项目在 P3 阶段**未下载任何图片**，而是：

1. 完整实现抓取脚本 `scripts/fetch_images.py`（许可白名单 + 检索/排除正则 + 分辨率与画幅过滤 + 联网通道自动探测），
   可在任何能访问 Commons 的网络环境一键复现；
2. 由 `assets/images/README.md` 记录实测证据与复现命令；
3. 应用在无图时**完整可用**（`src/data/images.py` 三种缺失场景全部安全降级，界面纯排版降级、不显示破图）。

**授权白名单**：仅接受 CC0 / CC BY / CC BY-SA / Public domain / GFDL；
**主动拒绝 NC（非商用）与 ND（禁演绎）**，避免授权瑕疵。
